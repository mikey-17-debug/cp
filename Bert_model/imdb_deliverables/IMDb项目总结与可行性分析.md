## 2. 数据与标签体系对比

### 2.1 第一期（中文）

- 36 个标签，包含 **Adult、短片、纪录片、真人秀、脱口秀、舞台艺术、戏曲、惊栗、鬼怪** 等格式类 / 噪声类 / 同义异体标签，题材与载体混杂；
- 影片级切分：train 36,656 / val 4,582 / test 4,583；
- 单标签按类型展开：train 89,357 / val 11,186 / test 11,167，平均每部影片 2.44 个标签；
- 训练集标签频次：剧情 43.1%、喜剧 24.0%、爱情 20.0%、动作 18.4%，最低频标签不足 0.1%。

### 2.2 第二期（英文）

- 剔除 Short、Documentary、Adult、News、Reality-TV、Talk-Show、Game-Show 共 7 个格式类，并丢弃 12 个出现次数 <10 的异体标签（Crimen、Drame、Terror 等），最终 21 个题材类；
- 影片级分层切分：train 165,555 / val 20,695 / test 20,695；
- 单标签取 primary 主类型：train 165,504 / val 20,694 / test 20,693；
- 训练集标签频次：Drama 38.97%、Comedy 25.71%、Animation 13.20%，最低 Film-Noir 0.46%（最大/最小相差约 85 倍）。

**对比结论**：第二期的标签体系更干净（按题材收敛、去掉载体类），但两期标签空间完全不同（36 vs 21），不能直接比较绝对指标；第一期 36 类中的格式类还会让模型在"题材"与"节目形态"之间产生语义混淆。

## 3. 训练结果对比

### 3.1 单标签

| 指标 | 中文一期 | 英文二期 | 说明 |
| --- | ---: | ---: | --- |
| 测试准确率 | 0.3248 | **0.5413** | 英文高 21.7 个百分点 |
| 测试 Macro-F1 | 0.1931 | **0.3590** | 英文接近中文的 1.9 倍 |
| 测试 Top-3 准确率 | 0.6990 | **0.8289** | 英文高 13.0 个百分点 |
| 多数类基线准确率 | 0.1770 | 0.2190 | Drama / 剧情 单类基线 |
| 相对多数类提升 | +14.8 pp | **+32.2 pp** | 英文模型学到的有效信号更强 |

> 中文指标取 `model/single_label/metrics.json`；英文取 `model_imdb/single_label/metrics.json`。压缩报告中的 fp32 复测值（中文 0.3251、英文 0.5411）与此有 ±0.0002 的批处理/精度差异，属正常范围。

### 3.2 多标签

| 指标 | 中文一期（阈值 0.5） | 英文二期（逐类阈值） |
| --- | ---: | ---: |
| Micro-F1 | 0.5777 | **0.6180** |
| Macro-F1 | 0.2887 | **0.5878** |
| 子集准确率 | 0.1828 | 0.2118 |
| 汉明损失 | 0.0474 | 0.0795 |

**关键差异不在 Micro-F1，而在 Macro-F1（0.289 vs 0.588）**：中文一期使用固定阈值 0.5，且 36 类中含大量长尾与格式类，多数稀有类几乎无法被召回（Macro-Recall 仅 0.236）；英文二期做了逐类阈值校准，长尾类的召回得到明显补偿。汉明损失中文更低，主要因为其正例比例更低，不能单独作为"更准"的证据。

### 4.2 体积与延迟（fp32 基线 → 代表变体）

| 项目 | 中文一期 | 英文二期 |
| --- | --- | --- |
| fp32 体积 / 参数量 | 390.7 MB / 102.3M | 418.4 MB / 109.5M |
| fp16/bf16 体积 | 195.6 MB（50.1%） | 209.6 MB（50.1%） |
| int8 体积 | 146.0 MB（37.4%） | 173.8 MB（41.5%） |
| 结构化剪枝 50% 体积 | 282.6 MB（72.3%） | 310.3 MB（74.2%） |
| 低秩 25% 体积 | 242.2 MB（62.0%） | 270.0 MB（64.5%） |
| GPU 单条延迟（fp32 → fp16） | 7.57 → 5.66 ms（单标签） | 6.92 → 5.38 ms（单标签） |
| GPU 单条延迟（fp32 → bf16） | 7.62 → 5.82 ms（多标签） | 6.35 → 4.98 ms（多标签） |
| INT8 CPU 批量吞吐 | 1.13×（单标签）/ 1.33×（多标签） | 1.31×（单标签）/ 1.24×（多标签） |

**对比结论**：

1. 两期结论一致——**半精度是 GPU 部署首选**，体积减半且精度无损；
2. 中文模型对剪枝/低秩更敏感：结构化剪枝 50% 的多标签 Micro-F1 从 0.578 掉到 0.076，低秩 25% 掉到 0.047，基本不可用；英文同变体仍有 0.377 / 0.341；
3. 中文 INT8 的精度损失小于英文（-1.15 vs -3.66 pp，单标签），但吞吐提升也更小（1.13× vs 1.31×），说明两期 INT8 收益随 CPU 算子与模型权重分布而异；
4. 中文一期未测半精度的 CPU 延迟与吞吐（表中为 —），与英文一期口径不一致，属于实验设计上的不足。

## 5. 可行性分析

### 5.1 技术可行性

| 维度 | 中文一期 | 英文二期 | 判断 |
| --- | --- | --- | --- |
| 单标签主类型 | Acc 32.5%，Top-3 69.9%，仅比多数类高 14.8 pp | Acc 54.1%，Top-3 82.9%，比多数类高 32.2 pp | 中文偏弱，英文可用 |
| 多标签题材 | Micro-F1 0.578，Macro-F1 0.289 | Micro-F1 0.618，Macro-F1 0.588 | 中文长尾失效，英文较均衡 |
| 精确标签集合 | 子集准确率 0.183 | 子集准确率 0.212 | 两期均不足以全自动发布 |
| 稳定性 | 验证/测试差距小 | 验证/测试差距小 | 均无明显过拟合 |

**结论**：

- **英文二期：有条件可行**——可用于机器预标注 + 人工复核、题材召回与检索过滤，不建议直接作为唯一标签来源；
- **中文一期：暂不具备独立上线条件**——单标签 32.5%、多标签 Macro-F1 0.289，且标签体系混杂，建议先重构标签与训练策略后重训，现阶段只能作为粗粒度筛选信号。

### 5.2 部署可行性

- **GPU 在线/离线服务**：两期均优先 FP16/BF16，体积减半、延迟下降、精度无损；
- **CPU 服务**：INT8 动态量化可把体积压到 37%~42%，吞吐提升 1.1~1.3×，精度损失 1~5 个百分点，适合离线批量打标；
- **受限存储/边缘**：结构化剪枝与低秩分解能压体积，但未微调时精度跌幅过大（中文尤甚），当前不建议上线；
- **非结构化剪枝 30%**：两期精度损失都很小，但稠密存储无体积收益，需要稀疏推理后端才能兑现价值。

### 5.3 工程与经济可行性

- 单模型约 100M 参数、400 MB，单卡即可训练与推理，硬件门槛低；
- FP16 单条 GPU 延迟 5~6 ms，可支撑离线批量与中低并发在线场景；
- 压缩产物均带 `optimization.json`，可重建、可回滚，具备复现基础；
- 但两期都缺少服务化压测（并发、内存、冷启动）与模型版本/监控体系，距离生产级部署仍有工程缺口。

## 6. 项目不足

以下问题按影响程度排序，前四项直接限制指标上限。

1. **标签体系不统一，两期不可比**
   - 中文 36 类混入载体/格式类（Adult、短片、纪录片、真人秀、脱口秀、舞台艺术）与同义异体标签（惊栗、鬼怪、戏曲），题材与节目形态语义混淆；
   - 英文虽剔除 7 个格式类，但仍需丢弃 12 个低频异体标签，说明原始数据的标签归一化不彻底；
   - 两期标签空间（36 vs 21）与数据规模（45,821 vs 243,093 部影片）差异巨大，指标不能横向比较。

2. **中文单标签的"类型展开"策略引入监督冲突**
   - 同一段剧情被复制成多条样本、分别标注为不同题材（既是"剧情"又是"喜剧"），模型被迫在同一输入上学习互相矛盾的标签，直接压低上限；
   - 英文改为 primary 后缓解了冲突，但代价是丢失影片的次要题材信息，仍不是理想口径。

3. **多标签阈值策略不一致**
   - 中文固定阈值 0.5，长尾类几乎无法召回（Macro-Recall 0.236、Macro-F1 0.289）；
   - 英文做了验证集逐类校准，Macro-F1 提升到 0.588；
   - 更关键的是：**压缩变体沿用了原模型的阈值，未按压缩后的概率分布重新校准**，INT8、低秩分解的精度损失被额外放大。

4. **类别不平衡未做任何处理**
   - 中文最高频类 43.1%、最低 <0.1%；英文最高 38.97%、最低 0.46%；
   - 两期均未使用 class weight、Focal Loss、重采样或长尾迁移，长尾类指标靠阈值校准"补"而非靠学习"学"。

5. **评估体系过于单薄**
   - 只有整体 Acc / Macro-F1 / Micro-F1 / 子集准确率 / 汉明损失，缺少逐类 Precision/Recall/F1、混淆矩阵与错误案例分析；
   - 没有置信度校准评估（ECE / reliability diagram），无法判断模型输出概率是否可用于阈值决策；
   - 只跑单次 seed（42），没有置信区间、交叉验证或显著性检验，小样本指标差异可能来自随机波动。

6. **实验设计不可比、结论外推有限**
   - 中文 3 epoch、英文 2 epoch；数据量相差 5 倍以上；文本长度分布不同；
   - 英文固定 2 epoch 且无早停/学习曲线，无法判断是否欠拟合或已饱和；
   - 两期都未做超参数搜索，学习率、batch、最大长度均沿用默认经验值。

7. **压缩实验方法学缺陷**
   - 所有剪枝/低秩均为"训练后一次性压缩、不做微调"，结论偏悲观，不能代表方法上限；
   - 非结构化剪枝在稠密存储下体积不变，却仍作为"压缩方案"参与对比，容易误导选型；
   - INT8 只测 CPU、未测 GPU；中文一期未测半精度 CPU 指标，英文二期补测后 CPU 延迟反而升高（285~295 ms），两期口径不一致；
   - 结构化剪枝只裁剪 FFN 中间层，未处理注意力层；低秩只作用于 FFN 投影，覆盖范围有限。

8. **数据质量与泄漏风险**
   - 英文仅按 (文本, 标签) 精确去重，近似重复的剧情简介、同一系列/翻拍影片可能跨 train/test；
   - 中文清洗主要按标签频次过滤，未做同义标签归一与文本规范化；
   - 两期都未统计缺失文本比例、文本长度分布与标签一致性，数据审计不足。

9. **文本信息利用不足**
   - 中文仅用 `summary`，英文用 `title + storyline`，均截断到 256 token，长简介信息丢失；
   - 未利用演职员、关键词、海报、时长、年代等可用字段，单模态文本上限明显。

10. **工程化与运维缺口**
    - 无 ONNX / TensorRT / 量化感知训练（QAT），推理加速仅停留在 PyTorch 层；
    - 无服务化压测（并发、显存、冷启动）、无模型版本管理与线上监控；
    - 报告与结果文件在两期之间字段不完全对齐（中文报告缺少数据集名称、阈值模式等元信息）。

## 7. 改进路线（按性价比排序）

1. **统一标签体系**：合并同义标签、剔除载体/格式类、建立中英文题材映射表，保证两期可比；
2. **中文重训**：改用 primary 单标签口径 + 验证集逐类阈值 + class weight/Focal Loss，优先把 Macro-F1 拉起来；
3. **压缩后微调与阈值重校准**：对结构化剪枝 75%、低秩 75% 做 1~2 epoch 微调，并对每个变体重新校准阈值，这是当前最高性价比的提升点；
4. **评估升级**：补充逐类 P/R/F1、混淆矩阵、ECE 校准曲线、Bootstrap 置信区间与错误案例分析；
5. **训练增强**：英文扩到 3~4 epoch 并加早停；尝试 deberta-v3-base / RoBERTa-base；中文补充 2~3 epoch 对照实验；
6. **长尾专项**：低频类过采样、类别加权、阈值分层策略（高频严格、低频宽松）；
7. **文本与多模态增强**：引入关键词、演职员、时长、年代等结构化特征，缓解简介缺失与截断问题；
8. **部署工程化**：ONNX/TensorRT 导出、INT8 变体的 GPU 方案评估、服务化压测与监控；
9. **模型蒸馏**：以 BERT-base 为教师蒸馏 4~6 层小模型，兼顾体积、延迟与精度。

---

## 8. 综合结论

- **英文二期：有条件可行（Conditional Go）**。单标签 Acc 54.1%、Top-3 82.9%，多标签 Micro-F1 0.618，配合 FP16（GPU）或 INT8（CPU）可落地到题材预标注、推荐召回与检索过滤；但子集准确率仅 0.212，必须保留人工复核。
- **中文一期：暂不可行（Not Ready）**。单标签 32.5%、多标签 Macro-F1 0.289，叠加标签体系混杂与固定阈值问题，需先完成标签重构与训练策略修正后重训。
- **两期共同结论**：压缩方面，半精度是唯一"零损失"方案；剪枝与低秩分解必须配合微调与阈值重校准才具备生产价值；项目整体仍缺少逐类评估、统计检验与服务化压测，属于"实验闭环完整、生产闭环未完成"的状态。
